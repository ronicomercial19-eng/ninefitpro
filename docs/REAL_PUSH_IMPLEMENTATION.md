# Push real — contrato de segurança\n\n## Estado do código\n\n- O cliente registra push_subscriptions.\n- A Edge Function send-push existe no repositório, mas precisa ser implantada e testada no Supabase.\n- A chave VAPID privada permanece exclusivamente nos secrets do Supabase.\n- smart-notifications não pode mais ser chamado publicamente: exige SMART_NOTIFICATIONS_SECRET.\n\n## Secrets necessários\n\n- VAPID_PUBLIC_KEY\n- VAPID_PRIVATE_KEY\n- VAPID_SUBJECT (por exemplo, mailto:suporte@seudominio.com)\n- PUSH_DISPATCH_SECRET: permite disparo interno entre jobs e send-push.\n- SMART_NOTIFICATIONS_SECRET: protege o job que avalia todos os atletas.\n\n## Regras de autorização\n\n1. Uma chamada comum a send-push exige JWT válido e só pode entregar uma notificação cujo user_id seja o usuário do JWT.\n2. Disparo para terceiros exige o header interno x-push-dispatch-secret e o secret correspondente.\n3. smart-notifications só aceita POST com x-smart-notifications-secret.\n4. O navegador nunca recebe secret de job, service-role ou VAPID privada.\n\n## Antes de liberar\n\n1. Implantar as duas funções no projeto correto.\n2. Configurar os dois novos secrets.\n3. Testar JWT do próprio usuário, tentativa cruzada entre usuários e job sem secret.\n4. Confirmar remoção de subscriptions 404/410 e uma entrega real em dispositivo.\n
